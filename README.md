# ⚙️ Volkgaard Tech - The Lexicanum (Portfolio & Service Portal)

เว็บไซต์นี้คือศูนย์กลางการให้บริการด้านไอที (IT Service Hub) และแฟ้มประวัติผลงานแบบมีชีวิต (Interactive Portfolio) ที่พัฒนาด้วยเทคโนโลยี Python และ Django เพื่อยกระดับมาตรฐานการบริการลูกค้าให้เป็นระบบ โปร่งใส และตรวจสอบได้

---

## 🛠️ 1. ขั้นตอนการเปิดโปรเจกต์บนคอมพิวเตอร์เครื่องใหม่ (Setup on a New Machine)

เมื่อต้องการนำโปรเจกต์นี้ไปรันบนคอมพิวเตอร์เครื่องอื่น ให้ทำตามขั้นตอนมาตรฐานดังต่อไปนี้:

### สเต็ปที่ 1: เตรียมความพร้อมของเครื่อง (Prerequisites)
ตรวจสอบให้แน่ใจว่าคอมพิวเตอร์เครื่องใหม่ได้ติดตั้งโปรแกรมพื้นฐานเรียบร้อยแล้ว:
- **Python**: (ดาวน์โหลดจาก python.org) จำเป็นต้องติ๊กถูกที่ช่อง `Add Python to PATH` ตอนติดตั้ง
- **Git**: (ดาวน์โหลดจาก git-scm.com) สำหรับใช้ดึงโค้ดจาก GitHub
- **VS Code**: โปรแกรมสำหรับใช้เขียนและแก้ไขโค้ด

### สเต็ปที่ 2: อัญเชิญคัมภีร์จาก GitHub (Git Clone)
เปิด VS Code ไปที่เมนู `Terminal` -> `New Terminal` แล้วใช้คำสั่งเพื่อดึงโค้ดลงมายังเครื่อง:
```bash
git clone [https://github.com/USERNAME/REPOSITORY_NAME.git](https://github.com/USERNAME/REPOSITORY_NAME.git)
cd REPOSITORY_NAME

สเต็ปที่ 3: สร้างสมองกลจำลอง (Virtual Environment)
เพื่อไม่ให้ไลบรารีของโปรเจกต์นี้ไปปะปนกับงานอื่นในคอมพิวเตอร์ ให้สร้าง Virtual Environment ใหม่โดยใช้คำสั่ง:
python -m venv venv

สเต็ปที่ 4: เปิดใช้งานสมองกล (Activate venv)
ก่อนติดตั้งโปรแกรมเสริมใดๆ ต้องสั่งเปิดสวิตช์ venv ทุกครั้ง:

สำหรับ Windows (Command Prompt / PowerShell):
venv\Scripts\activate

สำหรับ Mac / Linux:
source venv/bin/activate

(✅ ตรวจสอบความถูกต้อง: หากสำเร็จจะมีคำว่า (venv) สีเขียวปรากฏอยู่หน้าบรรทัดคำสั่งใน Terminal)

สเต็ปที่ 5: ติดตั้งอะไหล่เครื่องยนต์ (Install Dependencies)
สั่งให้ระบบอ่านรายชื่อไลบรารีจากไฟล์ requirements.txt และดาวน์โหลดมาติดตั้งให้ตรงเวอร์ชันเป๊ะๆ อัตโนมัติ:
pip install -r requirements.txt

สเต็ปที่ 6: ปลุกวิญญาณเครื่องจักร (Migrate Database)
ประกอบร่างฐานข้อมูลจำลอง (db.sqlite3) เพื่อเตรียมตารางจัดเก็บข้อมูลให้พร้อม:
python manage.py migrate

สเต็ปที่ 7: สร้างบัญชีผู้นำวิหาร (Create Superuser) - ทำเฉพาะกรณีที่ยังไม่มีฐานข้อมูล
หากต้องการเข้าใช้งานระบบหลังบ้าน (/admin) ให้สร้างบัญชีผู้ดูแลระบบ:
python manage.py createsuperuser

(จากนั้นให้กรอก Username, Email และ Password ตามที่ระบบสอบถาม)


สเต็ปที่ 8: สตาร์ทเซิร์ฟเวอร์ทดสอบ (Runserver)
สั่งเปิดใช้งานเว็บไซต์บนเครื่อง Local:
python manage.py runserver

เข้าเปิดดูเว็บไซต์ได้ทันทีผ่านเบราว์เซอร์ที่ลิงก์: 👉 http://127.0.0.1:8000/


🔄 2. ขั้นตอนการทำงานและอัปเดตระบบ (Day-to-day Workflow)
เมื่อมีการแก้ไขโค้ด อัปโหลดรูปภาพใหม่ หรือปรับเปลี่ยนโครงสร้างฐานข้อมูล ให้ยึดหลักการทำงานตามสถานการณ์ดังต่อไปนี้:

กรณีที่ 1: แก้ไขเนื้อหา, อัปโหลดรูป, หรือเพิ่มข้อมูลทั่วไปในหน้าเว็บ
วิธีทำงาน: งานกลุ่มนี้ (เช่น เพิ่มข่าวสารใหม่, แก้ไขข้อความประวัติส่วนตัว) สามารถเข้าไปจัดการผ่านระบบหลังบ้าน http://127.0.0.1:8000/admin หรือบนเซิร์ฟเวอร์จริงได้โดยตรง

ข้อควรระวัง: ข้อมูลและรูปภาพที่อัปโหลดผ่านระบบ Admin จะถูกบันทึกลงฐานข้อมูลและโฟลเดอร์ media/ โดยตรง ไม่จำเป็นต้องเขียนโค้ดใหม่

กรณีที่ 2: ปรับแต่งหน้าตาเว็บ (HTML / CSS / JS)
เมื่อมีการแก้ไขไฟล์ในโฟลเดอร์ templates/ หรือปรับแต่งความสวยงาม ให้บันทึกไฟล์และทำการส่งโค้ดขึ้น GitHub เพื่ออัปเดตเซิร์ฟเวอร์จริงตามสเต็ปนี้:

กด Save (Ctrl + S) ไฟล์ที่แก้ไขให้เรียบร้อย

เพิ่มไฟล์เข้าเตรียมส่ง:

Bash
git add .
ประทับตราบันทึกประวัติการแก้ไข:

Bash
git commit -m "Update frontend templates and design"
ส่งขึ้นคลังแสง GitHub:

Bash
git push
การนำขึ้นเซิร์ฟเวอร์จริง (Deploy): เข้าไปที่ Bash Console ของ PythonAnywhere สั่งดึงโค้ดลงมาด้วยคำสั่ง git pull จากนั้นไปที่แท็บ Web แล้วกดปุ่มสีเขียว Reload

กรณีที่ 3: ปรับเปลี่ยนโครงสร้างฐานข้อมูล (แก้ไขไฟล์ models.py) 🚨
เมื่อใดก็ตามที่มีการเพิ่มช่องเก็บข้อมูลใหม่, แก้ไขชื่อฟิลด์, หรือสร้างตารางใหม่ในไฟล์ models.py โครงสร้างของ Python จะไม่ตรงกับตารางฐานข้อมูลจริง ต้องทำการซิงก์ระบบใหม่ทุกครั้ง ดังนี้:

สั่งให้ระบบสร้างพิมพ์เขียวการเปลี่ยนแปลง:

Bash
python manage.py makemigrations
สั่งให้นำพิมพ์เขียวไปอัปเดตตารางฐานข้อมูลจริง:

Bash
python manage.py migrate
ทดสอบการทำงานด้วย runserver เพื่อให้แน่ใจว่าระบบไม่แสดงข้อผิดพลาด

ทำการบันทึกโค้ดขึ้น GitHub (git add . ➔ git commit ➔ git push)

บนเซิร์ฟเวอร์จริง (PythonAnywhere): เมื่อสั่ง git pull เสร็จแล้ว ต้องสั่งรันคำสั่งซิงก์ฐานข้อมูลบนเซิร์ฟเวอร์ด้วยคำสั่ง python manage.py migrate ก่อนที่จะกดปุ่ม Reload

💡 คำแนะนำเพิ่มเติมเพื่อความปลอดภัย: ตรวจสอบให้แน่ใจเสมอว่าไฟล์ .gitignore ได้ทำการบล็อกโฟลเดอร์ venv/ และไฟล์ db.sqlite3 เรียบร้อยแล้วก่อนส่งขึ้น GitHub เพื่อป้องกันไฟล์ขยะขนาดใหญ่และข้อมูลส่วนบุคคลรั่วไหล
